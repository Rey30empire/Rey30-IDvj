# Rey30 IDvj Data Folder
Rey30 IDvj stores your data locally in JSON format. Your data is yours alone.

## Open Rey30 IDvj Data Folder

Via Rey30 IDvj:
1. Settings (<Settings width={16} height={16} style={{display:"inline"}}/>) > General > App Logs
2. Click **Open Logs**


Via Terminal:

```bash
# Windows
cd %APPDATA%/Rey30-IDvj/data

# Mac
cd ~/Library/Application\ Support/Rey30-IDvj/data

# Linux (default — resolves via XDG_DATA_HOME)
cd ~/.local/share/Rey30-IDvj/data
```

<Callout type="info">
The data folder location can be customised from **Settings > General > Rey30 IDvj Data Folder**. Once changed, the path above no longer applies — check the Settings page for the active location.
</Callout>

## Directory Structure

Inside the data folder you will typically find:

```sh
/agent-workspace/
  /memory/
  /skills/
  /subagents/
  /sessions/<session_id>/
  /threads/<thread_id>/
/assistants/
  /jan/
    assistant.json
/extensions/
  extensions.json
  /@rey30-idvj/
    /assistant-extension/
    /conversational-extension/
    /download-extension/
    /llamacpp-extension/
    /mlx-extension/
    /rag-extension/
    /vector-db-extension/
/files/
/logs/
  app.log
/llamacpp/
  router.preset.ini
  /models/
    <org>/<repo>/
      model.yml
      model.gguf
/mlx/
  /models/
    <model_id>/
      model.yml
/threads/
  /<thread_id>/
    messages.jsonl
    thread.json
```

### `agent-workspace/`
The agent workspace, shared by the [Cowork](/docs/desktop/cowork) surface
(`nightly` channel only) and the [Rey30 IDvj Agent](/docs/agent). Memories (`memory/`),
skills (`skills/`), and saved subagent definitions (`subagents/`) live here
permanently. Each Cowork session gets an ephemeral sandbox under
`sessions/<session_id>/`, and chat threads that use agent tools get one under
`threads/<thread_id>/` — the agent can only write inside its own sandbox.

### `assistants/`
Where AI personalities live. The default one (`/assistants/jan/`):

```json

  "id": "jan",
  "object": "assistant",
  "created_at": 1750945742.536,

  "model": "*",

To complete a task, use tools step by step—each step should be guided by the outcome of the previous one.\nTool Usage Rules:\n1. Always provide the correct values as arguments when using tools. Do not pass variable names—use actual values instead.\n2. You may perform multiple tool steps to complete a task.\n3. Avoid repeating a tool call with exactly the same parameters to prevent infinite loops.",
  "tools": [
    {
      "type": "retrieval",

        "top_k": 2,
        "chunk_size": 1024,

      }
    }
  ],
  "file_ids": []
}
```

Parameters:

| Parameter               | Description                                                  | Type    | Default |
|------------------------|--------------------------------------------------------------|---------|---------|
| id                     | Assistant identifier                                         | string  | jan     |
| avatar                 | Assistant image                                              | string  | None    |
| object                 | OpenAI API compatibility marker                              | string  | None    |
| created_at             | Creation timestamp                                          | string  | None    |
| name                   | Display name                                                | string  | Rey30 IDvj     |
| description            | Role description                                            | string  | Default |
| model                  | Allowed models (* = all)                                    | string  | *       |
| instructions           | Default thread instructions                                 | string  | None    |
| file_ids              | OpenAI compatibility field                                  | string  | None    |
| tools                  | Available tools (retrieval only currently)                  | array   | retrieval|
| type                   | Tool type                                                   | string  | retrieval|
| enabled               | Tool status                                                 | boolean | true    |
| useTimeWeightedRetriever| Time-weighted retrieval toggle                            | boolean | false   |
| settings              | Tool configuration                                          | object  | None    |
| top_k                 | Max retrieval results                                       | number  | 2       |
| chunk_size            | Text chunk size                                             | number  | 1024    |
| chunk_overlap         | Chunk overlap amount                                        | number  | 64      |
| retrieval_template    | Response format template                                    | string  | None    |

### `extensions/`
Add-on central. Organization extensions live in `@rey30-idvj/`, solo ones in root.

### `logs/`
Debugging headquarters (`/logs/app.log`):
- **[APP]**: Core logs
- **[SERVER]**: API drama
- **[SPECS]**: Hardware confessions

### `llamacpp/models/` and `mlx/models/`
Installed models, organised per engine. Each model has its own `model.yml`:

```yaml
model_path: llamacpp/models/janhq/Jan-v3-4B-base-instruct-gguf/Jan-v3-4b-base-instruct-Q4_K_XL.gguf
name: Jan-v3-4B-base-instruct-gguf
size_bytes: 2999182272
embedding: false
model_sha256: 1dc700f26bfb10e53d1b2daebd86d4c5f2accc50fe13acd863c59453f9abfa48
```

## Conservar o retirar datos

Comprueba la carpeta activa en los ajustes y guarda una copia antes de retirar una instalación. Desinstalar la aplicación y borrar modelos o conversaciones son operaciones distintas. La migración conserva acceso a los datos anteriores; no los elimines hasta verificar su contenido.
