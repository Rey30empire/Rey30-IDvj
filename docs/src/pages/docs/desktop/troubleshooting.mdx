# Troubleshooting

## How to Get Error Logs

Consulta el registro de la aplicación para identificar el error antes de cambiar ajustes o reinstalar. Puedes abrirlo desde **Ajustes > General > Registros de la aplicación > Abrir registros**.

#### Through Rey30 IDvj Interface

1. Open **System Monitor** in the footer
2. Choose **App Log**

<br/>
<br/>

#### Through Terminal
**Application Logs (macOS)**
```bash
tail -n 50 ~/Library/Application\ Support/Rey30-IDvj/data/logs/app.log
```

App, server, and engine messages are all written to the same `logs/app.log` file (look for the `[APP]` / `[SERVER]` / `[SPECS]` tags). Local model output from llama.cpp appears prefixed with `[llamacpp-router]` and `[llamacpp-router stdout]` — these lines are the best source when a model fails to load or crashes.

The `logs/app.log` file lives inside your Rey30 IDvj data folder:

- **macOS:** `~/Library/Application Support/Rey30-IDvj/data/logs/app.log`
- **Windows:** `%APPDATA%\Rey30-IDvj\data\logs\app.log`
- **Linux:** `~/.local/share/Rey30-IDvj/data/logs/app.log`

<Callout type="warning">
Revisa y oculta claves, contenido privado y rutas personales antes de compartir un registro. Esta distribución no ofrece un servicio propio de recepción ni una política de retención de registros enviados.
</Callout>

## Rey30 IDvj Won't Start or Crashes on Launch

If Rey30 IDvj fails to open, closes immediately, or hangs on a blank window:

**1. Corrupt settings/store file**

Si el registro señala un archivo de ajustes dañado, conserva una copia de ese archivo y anota su ruta exacta. La carpeta activa puede ser la predeterminada (`Rey30-IDvj`) o una ruta personalizada. No borres el perfil ni presupongas que `store.json` contiene todos los ajustes. Sigue la [comprobación de la compilación](#broken-build) antes de intentar una recuperación.

**2. Another Rey30 IDvj instance is already running**

Rey30 IDvj es de instancia única. Si no aparece una ventana, comprueba su icono de bandeja y el proceso `Rey30-IDvj` en el Administrador de tareas antes de volver a abrirla. Cierra la instancia mediante su opción de salida cuando sea posible.

**3. Port 1337 already in use**

Rey30 IDvj's Local API Server binds to `127.0.0.1:1337` and does **not** fall back to another port automatically. If that port is taken (often by a previous Rey30 IDvj process that didn't exit cleanly), the server fails to bind. See [Port Conflicts](#failed-to-fetch-or-somethings-amiss-errors) below to find and free the port, or change it in **Settings** > **Local API Server**.


## Broken Build

1. Anota la versión mostrada por la aplicación, el sistema operativo y el mensaje exacto del registro.
2. En **Ajustes > General**, comprueba la ruta de datos activa. Conserva los modelos, chats y ajustes; respalda los archivos implicados antes de modificarlos.
3. Si usas este checkout en Windows, inicia `Iniciar-Rey30-IDvj.bat` desde la raíz y conserva el error que aparezca. La GUI y el CLI son ejecutables distintos: `Rey30-IDvj.exe` y `rey30-idvj.exe`, con directorios de compilación separados.
4. Consulta la [guía de construcción](/download) y verifica que el artefacto utilizado corresponde a ese checkout. Una compilación anterior no incorpora cambios de código posteriores.

No hay un canal propio de instaladores públicos configurado. Recompilar o sustituir el ejecutable no exige borrar la carpeta de datos. Si el fallo persiste, registra los pasos de reproducción y el fragmento relevante del log para diagnosticarlo.

## Cannot Relocate Data Folder on Windows

If you are unable to change the data folder location through Rey30 IDvj's interface on Windows, you can manually update it by editing the settings file:

1. Fully **quit Rey30 IDvj** (right-click the system tray icon → Quit)

2. Open File Explorer and navigate to:
   ```
   C:\Users\[username]\AppData\Roaming\Rey30-IDvj\
   ```

3. Open `settings.json` with a text editor (e.g. Notepad)

4. Find the `"data_folder"` field and update its value to your desired path, for example:
   ```json
   {
     "data_folder": "D:\\Rey30-IDvj"
   }
   ```

5. Optionally, **copy your data** from the old folder to the new folder to preserve your models, chat history, and settings

6. **Save** the file and **restart Rey30 IDvj**

Rey30 IDvj will now use the new data folder location.

<Callout type="info">
  Use double backslashes (`\\`) for path separators in the JSON file, e.g. `"D:\\Rey30-IDvj\\data"`.
</Callout>

## Troubleshooting NVIDIA GPU
To resolve issues when Rey30 IDvj does not utilize the NVIDIA GPU on Windows and Linux systems.

<Steps>

### Step 1: Verify Hardware and System Requirements

#### 1.1. Check GPU Detection
First, verify that your system recognizes the NVIDIA GPU:
**Windows:**
- Right-click desktop → NVIDIA Control Panel
- Or check Device Manager → Display Adapters
**Linux:**
```
lspci | grep -i nvidia
```
#### 1.2. Install Required components
**NVIDIA Driver:**
1. Install [NVIDIA Driver](https://www.nvidia.com/en-us/drivers/) for your GPU (NVIDIA driver **470.63.01 or higher**).
2. Verify installation:

```
nvidia-smi
```
Expected output should show your GPU model and driver version.

**CUDA Toolkit:**
1. Download and install [CUDA toolkit](https://developer.nvidia.com/cuda-downloads) (**CUDA 11.7 or higher**)
2. Verify installation:

```
nvcc --version
```
**Linux Additional Requirements:**
1. Required packages are installed:
```
sudo apt update
sudo apt install gcc-11 g++-11 cpp-11
```
See [detailed instructions](https://gcc.gnu.org/projects/cxx-status.html#cxx17).

2. Set up CUDA environment:
```
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/usr/local/cuda/lib64
```
See [detailed instructions](https://docs.nvidia.com/cuda/cuda-installation-guide-linux/index.html#post-installation-actions).

<Callout type="info">
Ensure your (V)RAM is accessible; some users with virtual RAM may require additional configuration.
</Callout>

### Step 2: Turn on GPU acceleration

Rey30 IDvj manages GPU usage automatically:
- Switches to GPU mode when supported
- Automatically selects GPU with highest VRAM

To verify GPU acceleration is turned on:
1. Open **Settings** > **Hardware**
2. Verify that **GPU Acceleration** is turned on
3. Verify your selected GPU(s) are visible in **System Monitor** from Rey30 IDvj's footer

<br/>
<br/>


### Step 3: Restart Rey30 IDvj

Restart Rey30 IDvj to make sure it works.

</Steps>

## AMD and Apple GPUs

Rey30 IDvj isn't limited to NVIDIA. The llama.cpp engine is built into Rey30 IDvj with the GPU backends for your
platform (CUDA and Vulkan on Windows and Linux, Metal on Apple Silicon), so there is no backend to
download or pick. Choose which GPUs it uses in **Settings** > **Hardware** > **GPUs**.

**AMD / Intel (Vulkan):**
- Requires up-to-date GPU drivers with Vulkan support.
- If you see a `ggml_vulkan ... error` in the logs, update your drivers and confirm Vulkan is
  installed (`vulkaninfo` on Linux).
- Make sure the GPU is turned on in **Settings** > **Hardware** > **GPUs**.

**Apple Silicon (Metal):**
- Metal acceleration is used automatically on M-series Macs; no setup needed.
- A `ggml_metal ... error` usually means the model is too large for available unified memory — use a
  smaller or more heavily quantized model.

**Intel Macs:**
- Not supported for local models: the bundled engine is built for Apple Silicon only. Remote and
  custom providers still work.

**GPU not detected after sleep (Linux):**
- After suspend/resume the driver state can go stale and Rey30 IDvj may report "No GPU detected." Restart
  Rey30 IDvj to re-probe the hardware.

## Model Won't Load or Crashes (llama.cpp)

When a local model fails to load or crashes mid-generation, Rey30 IDvj surfaces the error in the chat (as a
model error banner) and writes the underlying cause to [the logs](#how-to-get-error-logs). The most
common causes:

**Out of memory (RAM or VRAM)**
- *Symptom:* The model fails to load, or generation stops with an out-of-memory error.
- *Cause:* The model + context needs more memory than is available.
- *Fix:* Use a smaller or more quantized model; reduce the **context size**; offload fewer layers to
  the GPU (lower **GPU Layers**); or turn the GPU off in **Settings** > **Hardware** to run on CPU.

**Out of context size**
- *Symptom:* A banner says the model ran out of context size.
- *Cause:* The conversation (prompt) is longer than the model's configured context window.
- *Fix:* Click **Increase Context Size** in the banner, or raise **Context Size** in the model
  settings (default `8192`, up to `131072`). Larger context uses more memory.

**Model architecture not supported**
- *Symptom:* "This model's architecture is not supported by the current engine."
- *Cause:* The bundled llama.cpp is older than the model, or the file isn't a supported text model.
- *Fix:* Update Rey30 IDvj (the engine updates with the app), use a different model, or
  [run a newer `llama-server` yourself](/docs/desktop/remote-models/custom-endpoint#use-a-different-llamacpp-version).

**Model load timed out**
- *Symptom:* "The model took too long to load and was stopped."
- *Cause:* A large model on a slow disk didn't finish loading within the timeout (default 600s).
- *Fix:* Wait and retry, use a smaller model, store models on faster storage, or raise **Timeout for
  llamacpp** in **Settings** > **Model Providers** > **Llama.cpp**.

**Backend / driver error**
- *Symptom:* "The model process encountered an unexpected error," or a `cuda error:` /
  `ggml_vulkan`/`ggml_metal` line in the logs.
- *Cause:* GPU driver/runtime problem or an unsupported operation on the GPU's API.
- *Fix:* Update drivers. On a GPU reachable through both CUDA and Vulkan, try the other API in
  **Settings** > **Hardware** > **GPUs**, or turn the GPU off to run on CPU. Check the logs for the exact line.

### Common llama.cpp error messages

These strings appear in `logs/app.log` (on lines containing `rey30-idvj-llama-worker:`) when a model fails:

| Log message | Likely cause | Resolution |
| --- | --- | --- |
| `unknown model architecture: '<arch>'` | Engine too old, or not a supported text model | Update Rey30 IDvj; confirm the model is supported |
| `error loading model` / `failed to load model` | Corrupt or truncated GGUF, or partial download | Re-download the model |
| `missing tensor` / `wrong number of tensors` | Incomplete or mismatched GGUF | Re-download from a known-good source, or try another quantization |
| `failed to allocate ... buffer` / `out of memory` / `cudaMalloc` | Not enough RAM/VRAM for the model or KV cache | Smaller model, lower context, fewer GPU layers |
| `request (N tokens) exceeds the available context size (M)` | Prompt longer than the context window | Increase context size or shorten the conversation |
| `GGML_ASSERT(...)` | Engine bug or unsupported op on this GPU API | Try the other GPU API or the CPU; report upstream if it persists |

<Callout type="info">
For multi-shard (split) GGUF models, point the model file at **shard 1** (the standard llama.cpp
convention) so the rest are picked up automatically.
</Callout>

## Cloud Provider and Network Errors

Errors from cloud providers and custom endpoints surface as a chat error with the HTTP status:

| Status | Meaning | Fix |
| --- | --- | --- |
| `401` Unauthorized | API key is missing, wrong, or revoked | Re-check the key; confirm the right provider is selected |
| `403` Forbidden | Key lacks access to that model/endpoint | Verify the key's permissions and the model ID |
| `429` Rate limited | Too many requests, or out of quota/credits | Wait and retry; add fallback keys; check your billing |

If you've configured [API key fallbacks](/docs/desktop/remote-models/custom-endpoint#api-key-fallbacks)
and see "key rotation exhausted," **every** configured key failed with 401/403 — they're all
invalid or unauthorized.

**Custom endpoint won't connect:**
- Wrong **API type** (OpenAI- vs Anthropic-Compatible) makes requests fail even with a valid key.
- A `404` on every request usually means the **base URL is missing `/v1`** (or the wrong path).
- "Connection refused" / network errors mean the server isn't running or isn't reachable.

See the [Custom Endpoints](/docs/desktop/remote-models/custom-endpoint#troubleshooting) guide for details.

## Permission Denied

Esta distribución utiliza Tauri. Un error que menciona `app.asar` o `installExtension` corresponde al antiguo empaquetado Electron y no identifica un fallo del ejecutable actual por sí solo.

1. Confirma qué ejecutable estás abriendo y su versión. En este checkout de Windows, usa el BAT de inicio indicado en [Broken Build](#broken-build).
2. Abre **Ajustes > General > Registros de la aplicación > Abrir registros** y conserva el mensaje de error completo.
3. Comprueba la ruta concreta que aparece en el error y que tu cuenta puede leerla o escribirla según la operación solicitada. No cambies permisos de todo el perfil o de toda la caché npm por un error de una ruta distinta.
4. Antes de modificar un archivo afectado, cierra la aplicación y respáldalo. Conserva los modelos y chats; un error de permisos requiere identificar el archivo y la operación que fallaron.


## "Failed to fetch" or "Something's Amiss" errors

When you start a chat with a model and encounter a **Failed to Fetch** or **Something's Amiss** error, here are some possible solutions to resolve it:

**1. Check System & Hardware Requirements**
- Hardware dependencies: Ensure your device meets all [hardware requirements](troubleshooting)
- OS: Ensure your operating system meets the minimum requirements ([Mac](/docs/desktop/install/mac), [Windows](/docs/desktop/install/windows), [Linux](/docs/desktop/install/linux)
- RAM: Choose models that use less than 80% of your available RAM
  - For 8GB systems: Use models under 6GB
  - For 16GB systems: Use models under 13GB

**2. Check Model Parameters**
- In **Engine Settings** in right sidebar, check your `ngl` ([number of GPU layers](/docs/desktop/model-parameters)) setting to see if it's too high
- Start with a lower NGL value and increase gradually based on your GPU memory

**3. Port Conflicts**

If you check your [app logs](/docs/desktop/troubleshooting#how-to-get-error-logs) & see "Address already in use" or a bind failure on `127.0.0.1:1337` (Rey30 IDvj's default Local API Server port), check port availability:
```
# Mac
netstat -an | grep 1337

# Windows
netstat -ano | find "1337"
tasklist /fi "PID eq 1337"

# Linux
netstat -anpe | grep "1337"
```

If port `1337` is occupied, change it under **Settings** > **Local API Server** > **Configuration** > **Server Port**.
<Callout type="info">
  `Netstat` displays the contents of various network-related data structures for active connections.
</Callout>

Default Rey30 IDvj ports:
- Rey30 IDvj Local API Server: `1337`

**4. Factory Reset**

El restablecimiento de fábrica elimina datos. No lo uses como paso de diagnóstico de un error de conexión: conserva el perfil, los modelos y los chats, y registra primero el fallo concreto.

**5. Try a clean installation**

Comprueba la compilación y el ejecutable siguiendo [Broken Build](#broken-build). Esta distribución no tiene un canal público propio de releases configurado. Sustituir un ejecutable no requiere borrar la carpeta de datos.

<Callout type="warning">
This will delete all your Rey30 IDvj data.
</Callout>

## OpenAI Unexpected Token Issue
The "Unexpected token" error usually relates to OpenAI API authentication or regional restrictions.

**Step 1: API Key Sepup**
1. Get a valid API key from [OpenAI's developer platform](https://platform.openai.com/)
2. Ensure the key has sufficient credits & appropriate permissions

**Step 2: Regional Access**
1. If you're in a region with restricted access, use a VPN service from a supported region
2. Verify your network can reach OpenAI's API endpoints


## Performance Issues

**Models Running Slowly:**
- Enable GPU acceleration (see NVIDIA section above)
- Use appropriate model size for your hardware
- Close other memory-intensive applications
- Check Task Manager/Activity Monitor for resource usage

**High Memory Usage:**
- Switch to smaller model variants
- Reduce context length in model settings
- Enable model offloading in engine settings

**Frequent Crashes:**
- Update graphics drivers
- Check system temperature
- Reduce GPU layers if using GPU acceleration
- Verify adequate power supply (desktop systems)

## Rey30 IDvj CLI

### `rey30-idvj` is not recognized after updating the desktop app

Since v0.8.5 the desktop app no longer includes the `rey30-idvj` CLI or adds it to your `Path`. Updating from an earlier version removes the CLI that was bundled with the app. Install the CLI separately by following the [agent quickstart](/docs/agent/quickstart).

On Windows, the update leaves an old entry in your user `Path` that points at a folder with no CLI in it any more. You can remove it:

1. Open **System Properties** → **Advanced** → **Environment Variables**
2. Under **User variables**, select **Path** and click **Edit**
3. Select this entry and click **Delete**:
   ```
   C:\Users\<username>\AppData\Local\Programs\Rey30-IDvj\resources\bin
   ```
4. Click **OK** to save, then open a new terminal window.
